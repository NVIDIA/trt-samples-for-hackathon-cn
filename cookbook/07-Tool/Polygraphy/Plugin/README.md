# Polygraphy - Plugin mode

+ Steps to run (introduction is included in the script).

```bash
./main.sh
```

+ `polygraphy plugin` operates on the **ONNX graph**, not on plugin libraries: it matches a
  subgraph against a pattern shipped as `<plugin-dir>/<name>/pattern.py` and rewrites it into a
  single node. No `.so` is ever loaded, so `--plugin-dir` must point at a directory of pattern
  files. The workflow is `match` -> review `config.yaml` by hand -> `replace`.

+ The pattern and the workflow description come from the upstream example, kept in
  [`match_and_replace_plug/`](./match_and_replace_plug/README.md). The model it matches against is
  generated by [`build_toy_subgraph.py`](./build_toy_subgraph.py), which also plants two decoy
  subgraphs so the rejection reasons in `result-01.log` are visible.

+ Loading an actual plugin library is a different subject:
  [`../More/16-PluginReference/`](../More/16-PluginReference/README.md) measures why `--plugins`
  (and `LoadPlugins`, both of them `ctypes.CDLL`) cannot register an `IPluginCreatorV3One`, and
  what to use instead.
